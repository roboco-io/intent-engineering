クイックスタート

5分で最初の Intent Document を作成しよう。ツールは不要 -- マークダウンファイルだけでよい。

1

開始状態を選ぶ

自分が今どこにいるか正直に判断しよう。間違いはない。

一つ選択

seed        「アイデアはあるが、まだ具体的ではない」
exploring   「方向性はあるが、検証が必要」
clarified   「何を作るか正確に分かっている」
ヒント: ほとんどの人は seed か exploring から始める。実際には確信がないのに clarified から始めることは、間違ったものを最速で作る方法である。
2

INTENT.md を作成する

プロジェクトのルートに INTENT.md というファイルを作成する。以下のテンプレートをコピーして記入しよう。

seed または exploring の場合:

# INTENT — [Project Name]

> status: seed

## Why

Problem: [誰が、どのように困っているか?]
Hypothesis: [何がそれを解決すると思うか? 間違っていても構わない。]
Validation: [仮説が正しいかどうか、どうやって判断するか?]

## What

[seed の場合は空欄のままにする。exploring の場合は検証したい内容を書く。]

- [ ] [機能1 -- 一行で]
- [ ] [機能2 -- 一行で]

## Not

[思いつくことを書く。不確かな場合は (?) を付ける。]

- [例: 今のところモバイルアプリは作らない]
- [例: ユーザーデータを第三者に送信しない]

## Learnings

[今は空欄。探索しながら記入していく。]

clarified の場合:

# INTENT — [Project Name]

> status: clarified

## Why

Problem: [誰が、どのように困っているか?]
Goal: [成功とはどのような状態か?]
Metric: [どう測定するか? 数値を使う。]
Customer quote: [満足したユーザーが友人に何と言うか? 一文で。]

## What

- [ ] [機能1 -- 一行で]
- [ ] [機能2 -- 一行で]
- [ ] [機能3 -- 一行で]

User flow:
1. ユーザーが [A] を行う
2. システムが [B] を行う
3. 結果: [C]

Edge cases:
- [ケース1]
- [ケース2]

## Not

- Forbidden: [セキュリティ/倫理上のハードライン]
- Tech constraints: [例: `any` 型禁止、TypeScript のみ]
- Out of scope: [明示的に作らないもの]
- Quality bar: [例: レスポンスタイム200ms以内]

## Learnings

- [日付] [試したこと] -- [学んだこと]
3

探索して学ぶ

ここが Intent Engineering が従来の仕様書作成と分岐するポイントである。ドキュメントを書いて渡して終わりではない。Intent そのものを反復的に改善するのである。

何かを学ぶたびに -- プロトタイプ、ユーザーインタビュー、競合分析、あるいは失敗した実験からでも -- Learnings に追記する:

## Learnings

- [2026-04-01] プロトタイプv1を構築 -- ユーザーはダッシュボードを無視し、エクスポートに直行した
- [2026-04-03] 中小企業5社にインタビュー -- 本当の課題は分析ではなく請求書追跡だった
- [2026-04-05] 既存ツールXを発見 -- 計画の80%をカバーしている。残り20%のギャップにピボットする。

そして学んだことに基づいて Why / What / Not を更新する。ドキュメントは進化する。それがポイントである。

ヒント: 各学びは何かを変えるべきである。学んだのに Why/What/Not が何も変わらなかった場合、その学びが重要でなかったか、ドキュメントを更新していないかのどちらかである。
4

状態を遷移させる

準備ができたら次の状態に移行する -- またはエビデンスがそう示すならプロジェクトを終了する。

状態遷移

seed → exploring
  タイミング: 最初の実験を開始したとき。

exploring → clarified
  タイミング: Why/What/Not がすべて確信を持って埋められたとき。(?) マークが残っていないこと。

どの状態からでも → killed
  タイミング: エビデンスにより構築する価値がないと判明したとき、
        または既存のソリューションがカバーしているとき。
  アクション: 理由を Learnings に記録する。これは貴重な知識である。
5

AIに引き渡す

Intent が clarified になれば、AIは必要なものをすべて手にしている。Intent Document がAIエージェントのトップレベルのコンテキストとなる。

Claude Code を使用している場合、Not からコーディングルールを CLAUDE.md に抽出する:

# CLAUDE.md

## Intent Constraints
- TypeScript only, no `any` types
- Never modify user data without explicit confirmation
- Response time under 200ms for all API endpoints

あとはAIにタスク導出、コード作成、自己レビュー、デプロイを任せればよい。あなたはモニタリングし、フィードバックから学び、世界が変化したときに Intent を更新する。

以上である。 Intent Engineering はインストールするフレームワークではない。維持するファイルである。その力は Why/What/Not を書き、それ以外は何も書かないという規律にある。
